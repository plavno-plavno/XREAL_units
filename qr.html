Inspection tags

Targets for the glasses scanner. The QR is not part of the protocol — it holds plain text, and the app sends its contents as is. The four tags below match units in the demo registry; two more cover resolver edge cases.

What is sent after a scan
{ "commandName": "sendTextCommand", "text": "[glasses] QR scanned: url=<code contents>" }

The app adds the prefix. Don't put it in the code itself, or it will be sent twice.

Edge cases

2 tags

These two test parsing branches, not equipment: how the resolver behaves with no link and with a link that isn't in the registry.

Your own link

workbench

Any of EQ-1001…EQ-1004 just needs to appear somewhere in the string: the whole link is searched, case-insensitive. The browser then opens your page, while the name and document come from the registry.

01

The hyphen is required. The resolver looks for EQ-\d{3,}. A code with EQ1002 opens as an unknown page, and the assistant will know nothing about the unit.

02

Don't encode the prefix. The code holds only the contents; the app prepends [glasses] QR scanned:.

03

For real equipment, always use url=. The equipment_id argument takes a closed list of four demo ids; a real unit number in that form gets rejected.

04

Glasses are optional. You can send the same string by hand via sendTextCommand — on the wire it's identical to a scanned code. The "copy" button on each tag gives you the full string.
